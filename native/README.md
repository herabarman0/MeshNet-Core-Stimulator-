# Native core (phase 1)

A C++17 header-only port of the engine's data-plane building blocks, plus language-neutral conformance vectors
so that a Rust or Zig port can be checked against the same reference.

## What is here
| | |
|---|---|
| `conformance/vectors.txt` | 3,517 test vectors generated by the Java engine (the reference): 401 packets (decode + bit-exact re-encode), 6 malformed packets that must be rejected, 3,110 home-zone results |
| `native/cpp/mesh_core.hpp` | `Packet` (30 byte header, vector and allocation-free `encode_into` / `decode_view`), `home_zone`, `DedupCache`, `RouteCache`, `LocationDirectory` |
| `native/cpp/test_core.cpp` | runs every vector, the same unit cases as the Java tests, and 20,000 random junk packets (decode must never read out of bounds) |
| `native/cpp/bench.cpp` | encode + decode + home-zone lookup per second |

Not ported yet: the `MeshNode` state machine (routing, ACK/retry, discovery), `StoreAndForward`, crypto, storage.
The Java engine remains the only complete implementation.

## Build and test
    cd native/cpp && ./build_and_test.sh      # g++/clang, -Wall -Wextra -Wpedantic -Wconversion, AddressSanitizer + UBSan
    # Termux: pkg install clang; then use clang++ in place of g++ in the script

Regenerate the vectors after any change to the Java wire format or hashes (the Java test fails if the file is stale):
    java -cp <classes> com.herabarman.meshnet.core.ConformanceVectors conformance/vectors.txt

## Measured (one core of a shared virtual machine, micro-benchmark, 20 million iterations)
| | per packet (encode + decode + lookup) |
|---|---|
| Java (JIT) | 22 ns, about 45 million per second |
| C++ first version (`std::vector` everywhere) | 150-160 ns |
| C++ allocation-free API | 24-34 ns, about 30-40 million per second |

Packet processing is not the limit in any language: a phone radio delivers hundreds of packets per second.
A native core matters for other reasons: iOS (Java does not run there), microcontroller nodes (ESP32, LoRa boards),
no garbage collector, and one code base for every platform.

## Porting to Rust or Zig
1. Implement `Packet`, `home_zone` and the three caches.
2. Make the same vector file pass (`packet`, `bad`, `home` lines; format in `ConformanceVectors.java`).
3. Port `MeshNode` next and compare behaviour with the Java tests (`sim` module scenarios) before switching any app over.
Rust is the natural choice for a parser that reads bytes from strangers' radios: memory safety without a GC.
